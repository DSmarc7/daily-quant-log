# leetcode

One problem per day. Folder per problem named `<id>-<kebab-name>/`.

```
0217-contains-duplicate/
  solution.py    ← the accepted solution
  notes.md       ← approach, complexity, alternatives, pitfalls
```

## Two options to populate this folder

### Option A — LeetHub (recommended for the daily push)
Browser extension (Chrome/Edge) that auto-pushes every Accepted submission to GitHub. Setup details in `../SETUP.md`.

### Option B — Manual
Copy `_template/` into a new folder, paste your solution, write the notes.

## Why the notes matter

The `solution.py` alone is just a code dump. The `notes.md` is what makes this useful:
- Forces you to articulate the approach (most learning happens here)
- Becomes a searchable reference: "I've seen a problem like this, what was the trick?"
- Shows recruiters you understand the problems, not just brute-forced them

Don't write notes for trivial problems. Write notes for problems where you learned a pattern, got stuck, or saw a non-obvious trick.
